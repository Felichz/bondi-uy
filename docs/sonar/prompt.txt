# 🔍 **SONAR Analysis - Advanced Module Flow Discovery**

Analyze the codebase at **{{SCOPE}}** and create a comprehensive SONAR report following ACTUAL MODULE EXECUTION PATHS from entry points. This is NOT a file scan - trace real dependency chains and module usage.

## Analysis Configuration
- **Scope**: {{SCOPE}}
- **Project**: {{PROJECT_NAME}}
- **Output**: {{OUTPUT}}/modules.json
- **Strategy**: Follow imports and real usage, trace execution paths
- **Focus**: Map ALL modules relevant to {{USER_FLOWS}} execution

## Process Instructions

### 1. Entry Point Discovery
- Start from main entry points in {{SCOPE}}
- Identify the bootstrap sequence first

### 2. Module Flow Tracing Strategy
**CRITICAL**: This is dependency flow analysis, not file scanning.

For each module found:
- If **external** (IE node_modules) → register as dependency but DO NOT analyze deeper
- If **internal** → analyze recursively following REAL usage
- Identify: what it does, what it receives, what it produces
- Follow actual function calls and instantiations, not just imports

### 3. Analysis Rules
- **Follow the execution path**: If activate() calls func1() which calls func2(), that's the path
- **Track data flow**: How does information flow between modules?
- **Real usage only**: Don't analyze unused imports or dead code
- **Stop at externals**: Mark external dependencies but don't dive into stuff like node_modules or similar
- **Focus on USER_FLOWS**: Prioritize modules involved in the specified user flows

### 4. Module Identification
For each module, determine:
- **Concern**: What is this module's single responsibility?
- **Flow**: What does it receive → process → output?
- **Dependencies**: What other modules does THIS one actually use?
- **Role**: What architectural role does it play?
- **Depth**: Distance from entry point (automatically calculated by nesting)
