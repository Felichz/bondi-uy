**Explicación del Formato de Archivos GTFS**

Este documento describe el formato y la organización de varios archivos comúnmente encontrados en un feed GTFS (General Transit Feed Specification).

**1. `routes.txt`**

Este archivo define las rutas de transporte. Generalmente es un archivo CSV (valores separados por comas) con la siguiente estructura:

*   `route_id`: Un identificador único para cada ruta.
*   `agency_id`: (Opcional) Un identificador para la agencia de transporte si hay varias en el feed.
*   `route_short_name`: Un nombre corto para la ruta (ej. "103", "L2").
*   `route_long_name`: Un nombre más descriptivo para la ruta (ej. "Avenida Principal - Centro").
*   `route_desc`: (Opcional) Una descripción más detallada de la ruta.
*   `route_type`: Define el tipo de transporte (ej. 3 para autobús, 0 para tranvía, 2 para tren).
*   `route_url`: (Opcional) Una URL con más información sobre la ruta.
*   `route_color`: (Opcional) Un color para representar la ruta en mapas (formato hexadecimal RRGGBB).
*   `route_text_color`: (Opcional) Un color para el texto de la ruta sobre `route_color` (formato hexadecimal RRGGBB).

**2. `shapes.geojson`**

Este archivo describe la forma física (el trazado geográfico) de las rutas. Está en formato GeoJSON.

*   **Estructura General:**
    *   `type`: Siempre será `"FeatureCollection"`.
    *   `name`: Un nombre para la colección, en este caso `"shapes"`.
    *   `crs`: Define el sistema de referencia de coordenadas (CRS). Aquí se usa `"urn:ogc:def:crs:OGC:1.3:CRS84"`, que es el estándar WGS84 (latitud/longitud).
    *   `features`: Un array de objetos, donde cada objeto es una `"Feature"` (una forma individual).

*   **Estructura de cada `Feature` (forma):**
    *   `type`: Siempre será `"Feature"`.
    *   `properties`: Un objeto que contiene propiedades asociadas a esta forma.
        *   `shape_id`: Un identificador único para esta forma. Este `shape_id` se usa para enlazar esta forma con las definidas en `trips.txt`.
    *   `geometry`: Un objeto que describe la geometría de la forma.
        *   `type`: Será `"LineString"` para las formas de ruta, que representan una secuencia de puntos conectados.
        *   `coordinates`: Un array de arrays, donde cada array interno representa un punto `[longitud, latitud]` en el trazado de la ruta. La secuencia de estos puntos define la línea.

**3. `shapes.txt`**

Este archivo también describe la forma física de las rutas, pero en formato CSV. Es una representación alternativa o complementaria a `shapes.geojson`. Contiene los puntos que componen el trazado de una ruta.

*   `shape_id`: Identificador único para una forma. Este ID agrupa todos los puntos que pertenecen a la misma forma.
*   `shape_pt_lat`: Latitud del punto.
*   `shape_pt_lon`: Longitud del punto.
*   `shape_pt_sequence`: El número de secuencia de este punto dentro de la forma. Los puntos se dibujan en orden ascendente de `shape_pt_sequence`.

**4. `stops.geojson`**

Este archivo define la ubicación y propiedades de las paradas de transporte. Está en formato GeoJSON.

*   **Estructura General:**
    *   `type`: Siempre será `"FeatureCollection"`.
    *   `name`: Un nombre para la colección, en este caso `"stops"`.
    *   `crs`: Define el sistema de referencia de coordenadas, igual que en `shapes.geojson`.
    *   `features`: Un array de objetos, donde cada objeto es una `"Feature"` (una parada individual).

*   **Estructura de cada `Feature` (parada):**
    *   `type`: Siempre será `"Feature"`.
    *   `properties`: Un objeto que contiene propiedades asociadas a esta parada.
        *   `stop_id`: Un identificador único para la parada.
        *   `stop_name`: El nombre de la parada (ej. "CORUÑA y GRAL JULIO AMADEO ROLETTI").
        *   Otros campos opcionales de `stops.txt` (como `stop_code`, `location_type`, etc.) también pueden estar aquí.
    *   `geometry`: Un objeto que describe la geometría de la parada.
        *   `type`: Será `"Point"` para las paradas.
        *   `coordinates`: Un array con la `[longitud, latitud]` de la parada.

**5. `stops.txt`**

Este archivo define las paradas en formato CSV.

*   `stop_id`: Identificador único para la parada.
*   `stop_name`: Nombre de la parada.
*   `stop_code`: (Opcional) Un código corto o número para la parada, a menudo el que se muestra en las señales físicas.
*   `stop_lat`: Latitud de la parada.
*   `stop_lon`: Longitud de la parada.
*   `location_type`: Indica si es una parada (`0` o vacío), una estación (`1`), una entrada/salida (`2`), un nodo genérico (`3`) o un punto de embarque (`4`).
*   `parent_station`: (Opcional) Si la parada es parte de una estación más grande, este campo contiene el `stop_id` de la estación padre.
*   `stop_url`: (Opcional) URL con más información sobre la parada.
*   `wheelchair_boarding`: (Opcional) Indica la accesibilidad para sillas de ruedas (0: sin información, 1: accesible, 2: no accesible).

**6. `trips.txt`**

Este archivo define los viajes individuales para cada ruta. Es un archivo CSV.

*   `route_id`: Identificador de la ruta a la que pertenece este viaje (referencia a `routes.txt`).
*   `service_id`: Identificador del servicio al que pertenece este viaje (referencia a `calendar.txt` o `calendar_dates.txt`, que definen los días en que opera el servicio).
*   `trip_id`: Identificador único para el viaje.
*   `trip_headsign`: El texto que aparece en el letrero frontal del vehículo (ej. "URUGUAY Y FLORIDA", "INTERCAMBIADOR BELLONI").
*   `direction_id`: Indica la dirección del viaje para rutas con múltiples direcciones (ej. 0 para ida, 1 para vuelta).
*   `block_id`: (Opcional) Identificador que agrupa viajes consecutivos realizados por el mismo vehículo.
*   `shape_id`: Identificador de la forma que describe el trazado geográfico del viaje (referencia a `shapes.txt` o `shapes.geojson`).
*   `wheelchair_accessible`: (Opcional) Indica si el viaje es accesible para sillas de ruedas (0: sin información, 1: accesible, 2: no accesible).

**Resumen de la Organización de la Información:**

La información está interconectada:

*   `routes.txt` define las líneas de autobús o tren.
*   `trips.txt` define cada viaje específico que se realiza en una `route_id`, indicando su `service_id` (cuándo opera), su `trip_headsign` (destino) y su `shape_id` (trazado geográfico).
*   `shapes.txt` (o `shapes.geojson`) proporciona las coordenadas geográficas exactas (la "forma") para cada `shape_id` listado en `trips.txt`.
*   `stops.txt` (o `stops.geojson`) define la ubicación y nombres de todas las paradas.
*   (No proporcionados, pero parte del GTFS estándar) `stop_times.txt` conectaría los `trip_id` con los `stop_id`, especificando los horarios de llegada y salida en cada parada para cada viaje. `calendar.txt` y `calendar_dates.txt` definen los `service_id` indicando los días de la semana y fechas específicas en que los servicios están activos o inactivos.
